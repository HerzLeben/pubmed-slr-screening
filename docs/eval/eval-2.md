# eval-2：全ヒットをスクリーニングした評価（2026-09-29）

- 対象：eval-1 と同じ3本（31190844、33746596、37168849）。正解は `bench/reviews.jsonl` の `included_pmids`（7・9・11件）
- eval-1 との違い：検索式は変えず、上位200件の枠を外して全ヒット（`all_pmids`、695／436／473件）をスクリーニングした（DECISIONS 指示12）。rank 1〜200（batch_01〜10）は eval-1 の判定をそのまま使い、rank 201〜 を足した（batch_11〜35／11〜22／11〜24）

## 定義

eval-1 と同じ（[eval-1.md](eval-1.md) の定義の表）。ただし「スクリーニングした候補」は eval-1 では上位200件、eval-2 では全ヒット。Recall@k の分母「候補に入った組み入れ研究」も、eval-2 では全ヒットに入ったもの（＝検索 Recall（全ヒット）の分子）になる。

## 読み取れること（臨床の解釈ではなく、パイプラインの評価として）

1. 200件の枠を外すと、最終の Recall（全件）は 3本の計で 0.296 → 0.815（8/27 → 22/27）。31190844 は 0/7 → 5/7 で、全ヒットでの検索 Recall（0.714）に達した。33746596 は 9/9
2. 代わりにスクリーニングする件数は 600 → 1604件（2.7倍）、screener の起動は 60 → 162回、最終の候補は 98 → 237件、人の判断は 17 → 30件に増えた。31190844 の最終の候補は 145件（全ヒット 695件の21%）で、全文の確認の量が大きい
3. 全ヒット内では、Recall@50 は 0.800／1.000／0.900、Recall@20 は 0.800／0.778／0.800。スコアが満点で同点の組み入れ研究が多く、@20 に入るかどうかは同点内の rank（relevance 順）で決まっている（33746596 の 29812997 など）
4. screener の段で初めて落ちた2件（37168849）は、どちらも人が承認した基準（CAR-NK を I3 で除外、前臨床を E2 で除外）どおりの判定で、A・B が一致していた。ベンチマークの組み入れの範囲と、この基準の範囲が違うところ。検索で落ちた 28864289（NK-92 の aNK）と同じ種類
5. 次に人が決めること：検索で落ちた2件（31190844）のための P のブロックの見直し、37168849 の基準（CAR-NK・前臨床）をベンチマークに寄せるかどうか、最終の候補が多いこと（31190844 の145件）への対処
