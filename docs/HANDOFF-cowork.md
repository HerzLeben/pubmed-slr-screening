# Cowork への引き継ぎ（2026-09-29 時点）

Cowork のセッションで、このプロジェクトの方針や結果を相談するための引き継ぎ。ここに書いたのは要約で、正本は各ファイル（下の「読む順序」）。数字は docs/eval/eval-2.md から写した。

## 1. これは何か

- 系統的文献レビュー（SLR）のタイトル・抄録での一次スクリーニングを、Claude Code の subagent で行うワークフロー。TrialMind（Wang et al., npj Digital Medicine 2025）の手法を Claude Code で組み直した
- 流れ：適格基準の案（`/pico-to-criteria`）→ 人が承認 → 検索式（query-builder が公式 PubMed コネクタで試す）→ 人が承認 → `fetch_pubmed.py` で抄録を一括取得 → screener-a（基準を正順で読む）と screener-b（逆順）が基準ごとに 1/0/-1 と逐語引用で判定 → `adjudicate.py` が規則で裁定、割れたものは adjudicator が理由を書いて人に回す → HTML レポートで人が判断
- 評価は TrialReviewBench の血液がん・CAR-T のレビュー3本（31190844、33746596、37168849）。正解は元のレビューが組み入れた論文（7・9・11本）

## 2. 位置づけ（2026-09-29 人が決定）

- **業務での一次スクリーニングの代替ではなく、教育と手法（論文）の検証用**とする
- 理由：実際の SLR は PubMed 以外（Embase、Cochrane CENTRAL、臨床試験レジストリなど）も検索する必要があり、PubMed だけでは業務に足りない
- 記録：docs/HARNESS.md の末尾に1行。**requirements.md（1章の利用者像・「何を作るか」、4章「やらないこと」）はまだ直していない**（下の「未決」1）

## 3. 今の結果（eval-2：全ヒットをスクリーニング）

| 項目 | 値 |
|---|---|
| スクリーニングした件数（3本の計） | 1604件（695／436／473）、screener の起動 162回 |
| 最終の Recall（全件） | **22/27（0.815）**。31190844 は 5/7、33746596 は 9/9、37168849 は 8/11 |
| 最終の Recall（検索で拾えたものの中） | 22/24（0.917） |
| 最終の候補の件数 | 237件（145／59／33） |
| 人に回った件数 | 30件。この中に正解は無かった |
| 上位200件だけにした eval-1 | 最終の Recall 8/27（0.296）。枠を外して大きく上がった |

取りこぼし5件の内訳（詳細は eval-2.md「取りこぼし」）：

- 検索で落ちた：31190844 の2件（P のブロックに当たらない）、37168849 の1件（CAR を持たない NK 細胞の試験）
- screener で落ちた：37168849 の2件。CAR-NK（基準では CAR-T に当たらない）と、抄録に患者のデータが無いもの（前臨床として除外）。どちらも A・B の判定が一致し、承認済みの基準どおり
- 37168849 の3件は、元のレビュー自身が書いた基準（CAR-T）と、実際に組み入れた論文が食い違っているもの。答えと基準が食い違う2件を除いた補足の値は 22/25（0.880）

作業量：スコア順に全文を読むと、上位96／35／18件で正解のすべてに届く（breakdown_final.py）。

## 4. これまでに人が決めたこと（要点）

- 「不明（0）」は組み入れる側に倒す。モデルはすべて Sonnet。候補は当初 200件で、eval-2 で全ヒットに広げた
- **答えを見たあとで検索式・基準・規則を動かさない**（2026-09-29）。31190844 の P のブロックは直さない。37168849 の基準は変えない。候補が多い問題は規則を変えずに内訳で示す
- screener には CLAUDE.md や他の研究の判定を渡さない（`omitClaudeMd`、入力はバッチファイルだけ）
- 詳細と理由：docs/DECISIONS.md

## 6. 分担と進め方（これまでのやり方）

- Cowork：方針の相談、指示書の作成、Claude Code が読めない資料の確認（例：37168849 の元のレビューの全文は Cowork で NCBI efetch から取得。全文はリポジトリに置かない）、動画の切り出し
- Claude Code（このリポジトリ）：指示書を受けて実装・実行し、節目で commit と `snap/*` tag。想定外のことや人の決定は HARNESS.md、設計の変更は DECISIONS.md に残す
- 指示書は人が Claude Code に貼り、hook が docs/prompts/log.md に記録する。これまでの番号は「指示書16」まで
- Claude Code 側の決まり（CLAUDE.md）：requirements と実装が食い違ったら勝手に直さず止まる、`.env`・API key は読まない、コマンドは1つずつ、`/eval` は人だけが起動する
