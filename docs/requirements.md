# 要件 — PubMed SLR screening（2026-09-27 確定、2026-09-29 改訂（位置づけ、抽出）、2026-09-30 改訂（eval-3、抽出を範囲外に）、2026-10-01 改訂（抽出を範囲に戻す））

人が決めた要件と、その理由。実装・判断に迷ったらここを正とする（設計の詳細は `docs/design.md`）。

## 1. 何を作るか

レビューのテーマ（PICO）を入力に、PubMed から候補論文を集め、1本ずつ「このレビューに組み入れるべきか」を Claude Code の subagent が判定し、人が確認すべきものだけを残すワークフロー。系統的文献レビュー（SLR）の一次スクリーニング（タイトル・抄録）を、Claude Code でどこまで肩代わりできるかを、公開ベンチマークで確かめる。**教育と手法（論文）の検証用で、業務の一次スクリーニングの代わりにはしない**（2026-09-29 人が決定。実際の SLR は PubMed 以外も検索する必要があるため）

- **利用者像**：SLR の手法を学ぶ人と、LLM によるスクリーニングの論文（TrialMind など）を自分で確かめたい人。製薬の MA・HEOR・薬事で SLR を担当する人には、手順と限界を知る材料として示す
- **原著**：TrialMind（Wang et al., npj Digital Medicine 2025）。同じ手法を Claude Code で組み直す（「追試」とは言わない）

## 2. 決定事項

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 範囲 | ① 適格基準 → ② 検索 → ③ 候補取得 → ④ 2体の判定 → ⑤ 裁定 → ⑥ 人の確認 → ⑦ 研究特性の抽出まで（33746596・37168849、PMC の全文が取れる研究だけ）。**結果の統合はしない** | 1日で作り切れる規模。原著と同じ指標で答え合わせできる範囲。⑦は、位置づけを手法の検証用にしたので、原著の3つの作業（検索・スクリーニング・抽出）をなぞる（2026-09-29 人が決定）。**2026-09-30：⑦ は今回の範囲から外した（人が決定。完成は ①〜⑥）**。**2026-10-01：⑦ を範囲に戻した（人が決定）** |
| 2 | 「不明（0）」の扱い | **組み入れる側に倒す** | 見落としは業務上取り返せない。実際の SLR も「迷ったら全文確認へ進める」のが原則 |
| 3 | 2体の違い | 同じモデル・同じ基準で、**基準を読む順番を逆にする**（screener-a は正順、screener-b は逆順） | 条件を1つだけ変えるので、結果の違いを説明しやすい |
| 4 | モデル | 判定役2体・裁定役・検索役とも **Sonnet** | まず1回これで試す。結果を見て変えるなら DECISIONS に残す |
| 5 | 対象のレビュー | TrialReviewBench の免疫療法から血液がん中心の3本（下表） | テーマが近く、基準の作り方を比べやすい。組み入れ論文が少なく扱いやすい |
| 6 | 検索式 | Claude（query-builder）が作り、**人が確認して承認してから**本検索する | 検索は SLR の再現性の要。何で探したかに人が責任を持つ。原著との比較の流れ（eval-3）では人は判断しない（query-builder の案のまま） |
| 7 | 候補の上限 | eval-1 は上位200件。eval-2 で枠を外し、全ヒットをスクリーニングした（DECISIONS 指示12） | 1日で判定し切れる量（3本×200件×2体）。eval-1 で取りこぼしの大半（19件中16件）が200件の枠によるものだったため、eval-2 で外した |
| 8 | PubMed への接続 | 検索式の試行錯誤は **Anthropic 公式の PubMed コネクタ**（MCP、`pubmed@life-sciences` プラグイン）。決まった検索式での候補と抄録の一括取得は **短い Python スクリプト**（E-utilities を直接呼ぶ） | 公式は保守されアクセス制限も守られる。MCP は探索の道具、決まった大量処理は毎回同じ結果になるスクリプト。自作 MCP は第3作の主役に回す |
| 9 | 人が見る成果物 | **HTML のレポート**（要人判断リスト、最終の組み入れ候補リスト。抄録の引用箇所をハイライトし、A と B の判定を横に並べる） | 長い抄録を読みやすい。記事の画面としても見せやすい |
| 10 | 評価 | 原著と同じ**検索の Recall** と**スクリーニングの Recall@20 / @50**。比較は「screener-a だけ（原著相当の1体）」vs「2体＋裁定」。人に回った件数も並べる | 原著の数字と並べられる。2体にした効果と、その代わりに増えた人の手間を両方示す |
| 11 | 抽出の評価 | 答えは TrialReviewBench の `TrialReviewBench-data-extraction/<PMID>.csv`（整形は `bench/extraction/<PMID>.jsonl`）。指標は原著と同じ **Accuracy**。前後の空白と大文字・小文字をそろえて完全に一致したものは規則で正解、それ以外は人が1件ずつ正解／不正解と一言の理由を付ける（`results/extraction/human/`）。分母は本文が取れた7組の全項目で、「記載なし」は答えに値があれば不正解 | 原著の Accuracy は3人の採点者が人手で付けた（Methods）。採点は原著でも人がしているので、原著と同じ条件。完全一致は人が見ても正解になるので規則で済ませる（2026-09-29 人が決定） |
| 12 | 原著との比較 | **人の判断を挟まない流れ（eval-3）だけで比べる**：PICO → query-builder の検索式 → `/pico-to-criteria` の基準の案のまま → screener-a（1体）→ A のスコアで順位 → Recall@k。規則による裁定・adjudicator・人の判断は外す。eval-1・eval-2 は比較に使わない | 人が基準を直すと、原著（LLM が書いた基準をそのまま使う）と比べられない。原著も判定は1体（2026-09-29 人が決定、指示書19） |

## 3. 対象のレビュー（TrialReviewBench）

| PMID | テーマ（PICO の要約） | 組み入れ論文数 |
|---|---|---|
| 33746596 | 再発・難治性多発性骨髄腫（RRMM）に対する CAR-T 療法の有効性と安全性 | 9 |
| 31190844 | 血液がんに対する自家 CD19 CAR-T 療法の生存・有効性 | 7 |
| 37168849 | 再発・難治性急性骨髄性白血病（RR-AML）に対する CAR-T 療法の成績 | 11 |

- 正解は各レビューの `Involved_Citations`（組み入れ論文の PMID 一覧）。ベンチマークに非組み入れの候補は入っていないので、特異度は出さない
- **検索期間の上限は、元のレビューの出版時点に合わせる**（それ以降の論文は元のレビューが見られなかったため。上限の日付は人が承認する）

## 4. やらないこと

- 全文を読んでの最終判断、結果（アウトカム）の抽出と統合、バイアスリスク評価、メタ解析、臨床的な結論
- 画面のある Web アプリ（成果物は HTML のレポートまで）
- 自作の MCP
- PubMed 以外のデータベース（Embase、Cochrane CENTRAL、臨床試験レジストリ、学会抄録）の検索
- 業務の一次スクリーニングの代わりとして使うこと

## 5. 人が判断する場面（承認点）

原著との比較の流れ（eval-3）では人は判断しない。承認は動作の確認だけ（2026-09-29）。6・7 は抽出で行う（2026-10-01）

1. 適格基準の案 → 人が直して承認
2. 検索式と検索期間 → 人が承認
3. 1バッチ（20件）の試走結果 → 人が確認
4. 要人判断リスト → 人が1件ずつ判断（理由を一言残す）
5. 評価の全件実行 → 人が起動
6. extractor の試走（1本）→ 人が確認（動くかどうかの確認だけで、項目や答えは直さない）
7. 抽出の採点で、完全一致しなかった値 → 人が1件ずつ正解／不正解（原著の採点をなぞるもので、抽出の流れには人の判断を入れない）
