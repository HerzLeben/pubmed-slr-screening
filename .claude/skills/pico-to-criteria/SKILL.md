# PICO から適格基準の案を起こす

対象：$ARGUMENTS（レビューの PMID。複数可）

## 手順

1. `bench/reviews.jsonl` から対象 PMID の行を読み、`PICO`（P/I/C/O）と `Topic` を取り出す。`included_pmids`（正解）は**読まない・使わない**（基準が正解に合わせて作られるのを防ぐ）
2. 元レビューの出版日を PubMed で確認する（公式コネクタがあればそれで、無ければ E-utilities の esummary）。`pubdate`・`epubdate`・`sortpubdate` などの取れた日付を全部書き、検索期間の上限の案とその理由を1行で添える。上限は人が承認するまで**仮**
3. 基準を起こし、`reviews/<PMID>/criteria.md` に下の形で書く
4. 全部書き終えたら、人の承認を待って止まる。承認前に screener を起動しない

## 基準の書き方

- **1つの判定で答えられる粒度**にする。1つの基準に「かつ」「または」で2つの条件を入れない（例：「RRMM の患者に CAR-T を投与した」は P と I の2つに分ける）
- 各基準は、タイトルと抄録を読んで 1（満たす）/ -1（満たさない）/ 0（抄録からは分からない）で答えられる問いの形にする
- 包含（I1, I2, …）と除外（E1, E2, …）に分ける。除外基準は明示する（包含の裏返しを並べるだけにしない）
- 出典の列に、その基準が PICO のどの要素から来たかを書く。PICO に書かれていないもの（研究デザイン、出版の種類、言語など）を足すときは **「PICO 外」** と書き、人が採否を決められるようにする
- PICO の C が `N/A` のときは、比較群を条件にしない（単群試験を除外しない）
- O（アウトカム）は「いずれか1つを報告していれば満たす」形にし、全部の報告を求めない
- 臨床的な解釈や推測を足さない。PICO の語をそのまま使い、言い換えたときは元の語を併記する
- 0 は組み入れる側に倒す（requirements.md 決定事項2）。除外基準は、抄録で明らかに当てはまるときだけ 1 にする、と各基準に添える必要はない（screening-rules で扱う）

## criteria.md の形

```markdown
# 適格基準（案）— PMID <PMID>

状態：案（未承認）
Topic：<Topic>

## 元の PICO
- P：…
- I：…
- C：…
- O：…

## 検索期間の上限（仮）
| 項目 | 値 |
|---|---|
| 出典 | PubMed esummary（取得日 YYYY-MM-DD） |
| pubdate | … |
| epubdate | … |
| … | … |
| 上限の案 | YYYY/MM/DD（理由を1行） |

## 包含基準（すべて 1 または 0 なら組み入れ候補）
| ID | 問い | 出典 |
|---|---|---|
| I1 | … | P |

## 除外基準（どれか 1 なら除外）
| ID | 問い | 出典 |
|---|---|---|
| E1 | … | PICO 外 |

## 人に決めてほしい点
- （PICO 外の基準の採否、境界があいまいな語の解釈など）
```
