# 研究特性の抽出の規則

委任メッセージで渡された job ファイル（`results/extraction/jobs/<review>/<pmid>.json`）を1つ Read し、`fulltext` の全文を読み、`items` の全項目を抽出して、`output` に書かれた場所へ Write で1回書く。ほかのファイルは読まない・書かない。

## 1. 項目

- `items` に書かれた順に、1つずつ**すべて**答える。飛ばさない、足さない、並べ替えない
- 項目名は job に書かれた文字列を**そのまま**使う（言い換え、訳、略さない）

## 2. 値（`value`）

- 全文に書いてある内容を、短く書く。単位は残す
- 全文に無いことを推測しない。計算・換算・合算をしない（たとえば割合から人数を出す、群ごとの値を足す、など）
- 根拠にしてよいのは、この全文だけ。あなたの知識、ほかの研究、ほかの文書は使わない

## 3. 引用（`quotes`）

- 各項目に、値の根拠になる全文からの**逐語引用**を1つ以上書く
- 引用は全文のテキストにそのまま存在する文字列にする。省略記号、言い換え、縮約、離れた箇所のつなぎ合わせはしない。根拠が複数の箇所にあるなら、引用を複数に分ける
- 表から取った場合は、セルの文字列をそのまま引用する（表の1行はタブ区切りで書かれている。1つのセル、または1行のうち連続した部分を写す）
- 目安は1つ 300 字以内

## 4. 見つからないとき

- 全文のどこにも根拠が無ければ、`value` を `"記載なし"`、`quotes` を `[]` にする
- 「記載なし」は、全文を最後まで（表と図の説明を含めて）探してから使う

## 5. 出力 JSON の形

```json
{
  "review_pmid": "<job の review_pmid>",
  "pmid": "<job の pmid>",
  "items": [
    {"name": "<job の items[0] をそのまま>", "value": "<値>", "quotes": ["<全文の文字列>"]},
    {"name": "<job の items[1] をそのまま>", "value": "記載なし", "quotes": []}
  ]
}
```

- `items` は job の `items` と同じ数・同じ順
- `value` は空にしない（文字列）。`quotes` は文字列の配列
- Write はフックが検査し、不備があれば差し戻される（項目の過不足と順番、「記載なし」と引用の組み合わせ、各引用が全文に逐語であるか）。エラーに書かれた項目だけを直して、もう一度 Write する
