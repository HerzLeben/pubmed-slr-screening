# タイトル・抄録スクリーニングの判定規則

委任メッセージで渡されたバッチファイル（`results/batches/<review>/<a|b>/batch_<nn>.json`）を1つ Read し、全件を判定して、ファイルの `output` に書かれた場所へ Write で1回書く。ほかのファイルは読まない・書かない。

## 1. 読む順番

- バッチファイルの `criteria` を、**書かれている順番のまま**1件ずつ当てはめる（screener ごとに順番が違う。自分で並べ替えない）
- 1つのレコードについて全基準を判定してから次のレコードへ進む
- 根拠にしてよいのは、そのレコードの `title` と `abstract` だけ。あなたの知識、ほかのレコード、推測は使わない

## 2. 判定値

| 値 | inclusion（I） | exclusion（E） |
|---|---|---|
| 1 | 満たす | **該当しない**（除外に当たらない） |
| -1 | 満たさない | **該当する**（除外に当たる） |
| 0 | タイトル・抄録からは分からない | タイトル・抄録からは分からない |

- **E の向きに注意**：E の `text` は「除外に当たるか」の問いで書かれている。問いの答えが「はい（当たる）」なら **-1**、「いいえ（当たらない）」なら **1**
- タイトルにも抄録にも書かれていないことは **0**。推測で ±1 にしない。0 は組み入れる側に倒される（それでよい）
- 抄録が空（`""`）のレコードは、タイトルだけで判定する。タイトルで決まらない基準は 0
- 基準に `note` があれば、それは人が決めた境界の扱い。`text` と同じ重みで従う
- case report（症例報告）は、それだけでは除外しない

### E1（出版の種類）の範囲

その文書自身の患者データを含まず、他の研究を紹介・論評するもの（review、systematic review、meta-analysis、editorial、comment、news、学会報告の紹介）は E1 に**該当する（-1）**。自分の原著データを含む学会抄録や letter は**該当しない（1）**。「総説」と明記されていなくても、他の研究の結果だけを紹介・論評していれば -1。

## 3. 引用（quote）

- ±1 のときは必須。0 のときは `null`
- タイトルか抄録の**連続した1か所をそのまま写す**。大文字小文字も含めて同じ文字列にする
- 禁止：省略記号（…、...）、言い換え、縮約、語順の入れ替え、2か所のつなぎ合わせ、自分の言葉の補い
- 判定の根拠が分かる最短の範囲にする（目安 300 字以内）。どちらから取ったか（タイトル／抄録）は書かない
- 書いた引用はフックが機械的に照合する。見つからないと Write が差し戻される。そのときはエラーに出た PMID・基準の引用を、元の文字列から写し直す

## 4. 出力の形（docs/schema.md 5章）

```json
{
  "review_pmid": "31190844",
  "screener": "a",
  "batch": 1,
  "records": [
    {"pmid": "12345678",
     "criteria": [
       {"id": "I1", "verdict": 1, "quote": "patients with relapsed or refractory B-cell lymphoma"},
       {"id": "I2", "verdict": 0, "quote": null, "note": "標的抗原の記載なし"},
       {"id": "E1", "verdict": 1, "quote": "We conducted a phase 1 trial"}
     ]}
  ]
}
```

- `review_pmid`・`screener`・`batch` はバッチファイルの値をそのまま写す
- `records` はバッチの**全件**を、バッチファイルと同じ順に。1件も抜かさない
- 各レコードの `criteria` は**全基準を ID 順**（I1, I2, …, E1, E2, …）に並べる。判定した順（読む順）ではなく ID 順で出す
- `verdict` は -1・0・1 の整数だけ
- `note` は任意、1文まで（0 の理由など）
- **overall もスコアも書かない**（規則で導く）

## 5. 終わり方

Write が通ったら、最後のメッセージに書いたファイルのパスと件数だけを1行で書いて終える（例：`wrote results/screen/a/31190844/batch_01.json (20 records)`）。判定の要約や感想は書かない。
